## Network feeds

- **On a Mac, a feed with no screen now carries a picture.** It appeared on the
  network and sent nothing: macOS stops drawing a window nobody can see, and an
  output with no screen is exactly that. It now keeps drawing.
- **On Windows, a feed with no screen stays out of sight.** It opened a window
  on the laptop in front of whoever was using it. It now sits beyond the edge of
  the desktop, out of the taskbar, and never takes the keyboard.
- **Overlays key cleanly.** A lower third reached the switcher on a solid block.
  What is behind it is now transparent, and an open output switched between a
  full picture and an overlay is rebuilt with the right background.
- **The feed is the size you set.** Changing an open output's resolution
  applies straight away, and the frame is always exactly that size — a feed at
  an odd size is scaled by whatever receives it, and scaled text is soft.
- **Each output's row says whether its feed is on the network**, or why it is
  not — Screen Recording not allowed, the NDI runtime not installed — and can
  check that the network itself can see it.
- **Turning a feed on, or renaming it, applies to an output that is already
  open**, without closing it first.
- **The first Open no longer says the projector is not open.** macOS takes a
  moment to list a new window, and the feed now waits for it.

Settings → Stage no longer has its own "Send the screen over NDI" row; Displays
does it all. A church that had it on keeps its feed, on the Projector output and
under the same name, so the switcher still finds it where it was.

On a Mac, the first feed after this update asks for Screen Recording again.
Allow Pulpitry under Privacy & Security → Screen Recording, then reopen it.

## Updates

Pulpitry looks for a new version every time it starts, and tries again over the
next quarter of an hour if the network was not up yet.
