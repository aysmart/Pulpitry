Pulpitry can now update itself.

## New versions install themselves

When a newer version exists, a quiet line appears beside the projector warning:
**Version 0.8.0 is out — install it**. Press it and Pulpitry downloads the new
version, replaces itself and restarts. No browser, no download page, no dragging
anything into Applications.

Before this the only way to know was to visit the download page, which nobody
does — so churches stayed on old versions indefinitely without ever choosing to.

**Nothing happens until you press it.** The check runs once when the window
opens, never on a timer, and no download starts on its own. An application that
decided to update itself in the middle of a sermon would be worse than one that
is out of date.

**Every release is signed, and the signature is checked before anything is
installed.** That matters more here than it might sound: an updater that will
install whatever it is pointed at is a way onto every machine in every church
running this. Pulpitry verifies rather than trusts, and refuses an update that
does not carry our signature.

**The check carries nothing about you.** No identifier, no version, nothing about
the machine — the request is identical from every copy in the world. It is not
asked of us either: the manifest sits beside the installers on GitHub, which
already serves every download, so it never reaches our servers. There is a switch
in Settings for a machine that should touch nothing.

### This is the release you install by hand

Copies of 0.6.0 and earlier have no updater in them, so they cannot fetch this
one — install 0.7.0 the usual way. From here on, Pulpitry keeps itself current.

---

Not code signed. macOS will refuse to open it until you right-click and choose
Open; Windows SmartScreen will warn.

The engine that runs on your own machine needs no Node runtime. Azure and
Castavox subscriptions still need Node 20 or later, which is not bundled.
Scripture, songs, slides and the projector work without it.
