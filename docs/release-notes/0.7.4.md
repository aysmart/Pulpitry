Pulpitry starts on a Windows machine with no Vulkan driver. Properly, this time.

## The one that 0.7.3 did not fix

0.7.3 tried to solve this by shipping the Vulkan loader with Pulpitry. It does
ship it — into a folder Windows never looks in when it is starting a program, so
the machines that could not open Pulpitry still could not open it.

Pulpitry on Windows now transcribes on the processor and requires no Vulkan
driver at all. Every machine starts.

## What this costs

On a Windows PC with a usable graphics card, transcription on the machine was
using it and now uses the processor instead, so it is slower there. Settings
tells you what your machine actually manages, and a subscription is the answer
for one that cannot keep up.

We would rather be slower everywhere than fastest on some machines and dead on
others. Using the graphics card again is work we will do properly rather than
guess at twice.

Castavox is unaffected and still uses the graphics card: its speech engine is a
separate program, and the loader sits in the folder Windows does search.

---

Not code signed. macOS will refuse to open it until you right-click and choose
Open; Windows SmartScreen will warn.

The engine that runs on your own machine needs no Node runtime. Azure and
Castavox subscriptions still need Node 20 or later, which is not bundled.
Scripture, songs, slides and the projector work without it.
