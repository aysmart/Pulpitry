A small release. Nothing changes in how Pulpitry is used; what changed is
underneath, where the two applications had been drifting apart.

## One way of reaching a model, not two

Summaries and scripture suggestion talk to a language model — your own Azure AI
Foundry deployment, or ours if you are on a Castavox subscription. Pulpitry and
Castavox each carried their own copy of how that conversation works: how it
authenticates, how it retries a deployment that refuses strict JSON, how it
reads the reply.

Two copies is how a fix reaches one application and not the other, which had
already happened twice and put a page of somebody else's error markup in front
of an operator both times. There is one copy now, shared between them.

Two things improved by being made common. A deployment that complains about
`json_object` rather than `response_format` now gets its retry here as well as
in Castavox; and the retry is decided on the whole reply rather than the first
300 characters of it, so a deployment that mentions the parameter late in a
long complaint is no longer read as simply broken.

## Installing

macOS is Apple silicon only. Not code signed — macOS will refuse to open the
app until you open it once from the right-click menu, and Windows SmartScreen
will warn.

Linux: `.deb`, `.rpm` and AppImage, x86_64.

Transcription needs Node 20 or later, which is not bundled. Scripture, songs,
slides and the projector work without it.
